Методика

Откуда берутся данные в досье, как они сверяются и где у автоматического анализа есть ограничения.

1. Документы

Текст извлекается из PDF (PyMuPDF), DOCX (python-docx) и DOC (LibreOffice). Анкета Tilda разбирается по полям: ФИО, трек, дата рождения, гражданство, место работы, PhD, подразделение и контакт в ИТМО, рекомендатели, ссылки на профили.

В CV и proposal автоматически ищутся ORCID, Scopus Author ID, Google Scholar, ResearcherID, DOI и заявленные кандидатом метрики (H-index, цитирования) — они затем сверяются с внешними данными.

Приоритет идентификаторов: введено вручную → анкета → CV.

2. Публикации

  • OpenAlex — основной источник метаданных: DOI, тип, журнал, ISSN, полный список авторов и позиция кандидата, цитирования. Автор находится по ORCID; разделённые профили OpenAlex подтверждаются совпадением названий работ с Google Scholar.
  • ORCID — работы с DOI, которых нет в профиле OpenAlex.
  • Google Scholar — публичный профиль: H-index, i10, цитирования, список работ (в т. ч. не индексируемые в OpenAlex).

Записи объединяются по DOI и по нормализованному названию; при наличии препринта и опубликованной версии остаётся опубликованная. Период: {{ default_from }}–{{ this_year }} (четыре полных года и текущий), настраивается.

3. Квартили журналов

Квартиль берётся из SCImago Journal Rank (SJR) по ISSN (или точному названию журнала) за год публикации. SJR публикуется с задержкой, поэтому для лет после {{ sjr_year }} используется последний доступный рейтинг — год указан в досье. Для каждой статьи сохраняются лучший квартиль, год, значение SJR и все предметные категории с их квартилями.

Квартили Web of Science (JCR) являются коммерческими данными Clarivate и в MVP не используются.

4. H-index

  • Google Scholar — из публичного профиля (всего и с {{ this_year - 5 }} г.).
  • Scopus — через Scopus Author Retrieval API (нужен ключ Elsevier и доступ из сети ИТМО) либо вводится вручную.
  • OpenAlex — открытый аналог, полезен для сверки.

5. Исследовательский профиль

При подключённой LLM (DeepSeek или Claude — DEEPSEEK_API_KEY / ANTHROPIC_API_KEY) модель читает CV, proposal и проверенный список публикаций и формирует резюме, интересы, методы, компетенции, прикладные направления, ключевые слова и заметки для эксперта (структурированный вывод). Без ключа используется прозрачная эвристика: интересы Google Scholar, ключевые слова ORCID, темы OpenAlex.

6. Подбор подразделений ИТМО

Научная карта ИТМО собирается с официальных страниц подразделений на en.itmo.ru (факультеты, институты, научные центры, лаборатории): название, руководитель, сайт и описание направлений.

Профиль кандидата (тема проекта, интересы, методы, ключевые слова, темы OpenAlex, названия публикаций) сравнивается с описаниями подразделений: 75% — семантическое сходство многоязычной модели paraphrase-multilingual-MiniLM-L12-v2 (работает локально, понимает русский и английский), 25% — совпадение терминов (TF-IDF). Для каждого подразделения показано, какие публикации и интересы дали совпадение. С ключом LLM модель переранжирует топ-12 и предлагает направления сотрудничества.

Подразделение, указанное в заявке, находится в каталоге, и его место в рейтинге показывается как проверка качества.

7. Ограничения

  • Google Scholar может временно ограничить доступ (CAPTCHA) — досье собирается без него, это видно в разделе «Источники».
  • Без ORCID профиль OpenAlex определяется по имени и совпадениям со Scholar; при низкой уверенности выводится предупреждение.
  • Позиция автора не определяется в сокращённых списках авторов Google Scholar («…»).
  • Все внешние ответы кэшируются на {{ 14 }} дней в data/cache.
